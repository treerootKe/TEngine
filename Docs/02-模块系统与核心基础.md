# 02 模块系统与核心基础

源码位置：`Assets/TEngine/Runtime/Core/`、`Assets/TEngine/Runtime/Module/RootModule.cs`

## 1. ModuleSystem —— 框架模块的注册与轮询中枢

文件：`Core/ModuleSystem.cs`（纯静态类，不挂场景）

**获取模块的约定（重点）：**
```csharp
// 只能用接口取，且接口名去掉开头 I 就是实现类名
ModuleSystem.GetModule<IResourceModule>()   // → TEngine.ResourceModule
ModuleSystem.GetModule<IAudioModule>()      // → TEngine.AudioModule
```
实现机制（ModuleSystem.cs:81）：`"TEngine." + "IResourceModule".Substring(1) + ", TEngine.Runtime"` 拼出实现类全名 → `Type.GetType` → `Activator.CreateInstance`。所以**新框架模块必须满足：接口以 I 开头、实现类同命名空间同程序集、有无参构造**。

**内部数据结构：**
- `_moduleMaps`：接口类型 → 模块实例（懒创建，取过即缓存）
- `_modules`：按 `Module.Priority` 降序的链表（优先级高的先轮询、**后** Shutdown）
- `_updateModules` → `_updateExecuteList`：实现了 `IUpdateModule` 的模块的扁平缓存数组，脏标记触发重建 —— Update 循环里零装箱零分配

**生命周期：**
- 创建时立即 `module.OnInit()`
- `ModuleSystem.Update(dt, unscaledDt)` 每帧由 RootModule 喂入
- `Shutdown()` 逆优先级逐个关闭，最后清 MemoryPool、释放 Marshal 缓存

**注册自定义模块（不走命名约定时）：**
```csharp
ModuleSystem.RegisterModule<IMyModule>(new MyModule()); // 接口键手动注册
```

模块基类（Core/Module.cs）：`abstract class Module { int Priority; OnInit(); Shutdown(); }`，需要轮询再实现 `IUpdateModule.Update()`。

## 2. RootModule —— 框架的 MonoBehaviour 宿主

文件：`Module/RootModule.cs`。场景 `main.unity` 上的同名组件。

职责：
1. Awake 装配三件 Helper（`DefaultTextHelper/DefaultLogHelper/DefaultJsonHelper`，序列化字段可换）
2. 应用全局设置：帧率 120、`Time.timeScale`、后台运行、永不休眠
3. 每帧 `ModuleSystem.Update(GameTime.deltaTime, GameTime.unscaledDeltaTime)`；Fixed/LateUpdate 里刷新 `GameTime.StartFrame()`（帧内缓存时间，避免多处访问 Time 的开销）
4. `Application.lowMemory` → 释放对象池 + `ResourceModule.OnLowMemory()`
5. 游戏暂停三连：`PauseGame()/ResumeGame()/ResetNormalGameSpeed()`

注意 `OnDestroy` 里 `#if !UNITY_EDITOR` 才 `ModuleSystem.Shutdown()` —— 编辑器停止 Play 不走完整关闭流程。

## 3. UpdateDriver —— 隐藏驱动器

文件：`Module/UpdataDriver/UpdateDriver.cs`（GameEntry 第一行 `GetModule<IUpdateDriver>()` 就是为创建它）。

实现：`OnInit` 创建一个隐藏 GameObject 挂 `MainBehaviour`，把 Unity 的协程/Update/FixedUpdate/LateUpdate/OnDrawGizmos 以**事件监听器**形式对外分发：
- `AddUpdateListener/RemoveUpdateListener` 等
- `StartCoroutine/StopCoroutine` —— **这就是 `Utility.Unity.StartCoroutine` 的实体**，流程类里所有协程都跑在这
- 热更侧 `SingletonSystem` 也挂它的 Update 事件（01 篇第 3 节）

## 4. Settings —— 配置资产入口

文件：`Module/Settings/Settings.cs`（场景组件）+ `Assets/TEngine/Settings/` 下三个 ScriptableObject：

| 资产 | 用途 |
|---|---|
| `ProcedureSetting.asset` | 可用流程类名列表 + 入口流程（ProcedureLaunch） |
| `AudioSetting.asset` | 音频分组配置（见 06 篇） |
| `UpdateSetting.asset` | 热更/更新配置（见 07 篇） |

用法：`Settings.ProcedureSetting` / `Settings.AudioSetting` / `Settings.UpdateSetting`。编辑器下 UpdateSetting 有资产兜底查找逻辑（Settings.cs:44-54）。

## 5. 其余 Core 件速览

| 文件/目录 | 是什么 | 业务侧怎么用 |
|---|---|---|
| `Log/` | 分级日志（Fatal..Debug），宏控制编译期裁剪（菜单 `TEngine/Log Scripting Define Symbols`） | `Log.Info("x={0}", x)`（格式化占位，不产生字符串拼接分配） |
| `GameTime/` | 帧内缓存的 deltaTime/unscaledDeltaTime | 读时间统一走 `GameTime.XXX` |
| `MemoryPool/` | 类实例回收池（`IMemory` 接口：Clear()） | `MemoryPool.Acquire<T>()` / `MemoryPool.Release(obj)`；框架内部 AssetObject/GameEventMgr 都靠它 |
| `DataStruct/` | 参考实现（CRC 等） | 基本不直接用 |
| `Constant/` | 框架常量（Setting 键名等） | `Constant.Setting.Language` |
| `Utility/` | 15 个工具类：Text/Json/Unity(协程,AddDestroyListener)/Path/Marshal/Converter/File/Assembly/PlayerPrefs... | `Utility.Unity.StartCoroutine(...)`、`Utility.PlayerPrefs.GetString(...)` |
| `GameEvent/` | 事件系统 | 专门一篇：05 |

## 6. 加一个框架模块的最小步骤（练习用）

1. `Assets/TEngine/Runtime/Module/MyThing/IMyThingModule.cs`：
```csharp
namespace TEngine
{
    public interface IMyThingModule
    {
        void DoSomething();
    }
}
```
2. 同目录 `MyThingModule.cs`：
```csharp
namespace TEngine
{
    internal sealed class MyThingModule : Module, IMyThingModule, IUpdateModule
    {
        public override int Priority => 1;      // 数值大先轮询
        public override void OnInit() { }
        public override void Shutdown() { }
        public void Update(float a, float b) { }
        public void DoSomething() { }
    }
}
```
3. 使用：`ModuleSystem.GetModule<IMyThingModule>().DoSomething();` 首次调用自动创建并 OnInit。
