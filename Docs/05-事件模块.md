# 05 事件模块（GameEvent）

源码：`Assets/TEngine/Runtime/Core/GameEvent/`（含 SourceGenerator.dll / GameEventAnalyzer.dll 两个编译期插件）

## 1. 文件结构

| 文件 | 职责 |
|---|---|
| `GameEvent.cs` (809行) | 全局静态门面：Add/Has/Remove/Send/Get<T> |
| `EventDispatcher.cs` | 真正的注册表与分发循环 |
| `EventMgr.cs` | GameEvent 持有的管理器壳 |

| `EventInterfaceAttribute.cs` | `[EventInterface]` + `EEventGroup` 枚举 |

| `SourceGenerator/Analyzer.dll` | 编译期扫描 [EventInterface] 接口，生成 GameEventHelper 等胶水代码 |

## 2. 两种用法

### 用法 A：int/string 直接事件（点对点通知）

```csharp
// 定义事件号（建议集中管理）
public static class GameEventDef { public const int ScoreChanged = 10001; }

// 订阅（int 或 string 键等价，string 内部转 RuntimeId）
GameEvent.AddEventListener<int>(GameEventDef.ScoreChanged, score => { ... });
GameEvent.AddEventListener<string>("UILoadUpdate.RefreshVersion", OnRefresh);

// 发送（0~6 个泛型参数）
GameEvent.Send(GameEventDef.ScoreChanged, 120);
GameEvent.Send("UILoadUpdate.RefreshVersion");

// 注销（handler 引用要留着）
GameEvent.RemoveEventListener(GameEventDef.ScoreChanged, handler);
```
流程链里现成例子：`ProcedurePreload.cs:49` 用 `"UILoadUpdate.RefreshVersion"` 通知启动 UI 刷新版本号。

### 用法 B：接口事件（推荐，编译期生成、面向模块通信）

1. **声明接口**（放 `GameLogic/IEvent/`，如自带 `ILoginUI.cs`）：
```csharp
[EventInterface(EEventGroup.GroupUI)]   // GroupUI=UI交互 / GroupLogic=逻辑层内部
public interface ILoginUI
{
    void ShowLoginUI();
    void CloseLoginUI();
}
```
2. SourceGenerator 会在编译时为接口生成事件号与注册胶水（`GameEventHelper.Init()` 在 GameApp.Entrance 里调用，GameApp.cs:27 —— 全仓库搜不到 GameEventHelper 类定义，它是**生成代码**，别手写）。
3. **实现并注册**：任意类实现接口，框架按类型自动路由；**调用**：
```csharp
GameEvent.Get<ILoginUI>().ShowLoginUI();
```
（GameApp.cs:38 注释掉的示例就是这个写法。）

## 3. 窗口内事件：AddUIEvent + 自动注销

裸用 A 方案容易忘记注销。UIWindow/UIBase 内置了记录簿模式（UIBase.cs:282-332）：

```csharp
// 窗口子类里（内部走池化的 GameEventMgr 记账）
protected override void RegisterEvent()
{
    AddUIEvent(GameEventDef.ScoreChanged, OnScoreChanged);        // 无参
    AddUIEvent<int>(GameEventDef.ScoreChanged, OnScoreChanged2);  // 带参
}
// 窗口 InternalDestroy → RemoveAllUIEvent() 批量注销，无需手写
```

自己写的非 UI 类要局部记账，可直接复用 `GameEventMgr`（IMemory，Clear() 时批量 RemoveEventListener）。

## 4. 机制要点

- 分发是**同步**的：Send 所在线程立刻逐个回调；不要在回调里注销自己正在被遍历的 handler 之外的复杂操作谨慎
- string 事件经 `RuntimeId.ToRuntimeId` 转成 int 键统一进一张注册表 —— int 与 string 两套 API 底层同源
- `GameEvent.Shutdown()` 清空全局事件表（框架重启时用）
- 事件组 `EEventGroup` 目前只有 GroupUI/GroupLogic 两个，用于生成器侧归类，运行时无隔离语义

## 5. 选型建议

| 场景 | 用法 |
|---|---|
| UI 窗口监听业务刷新 | `AddUIEvent`（自动注销） |
| 跨模块调用（UI↔逻辑、系统↔系统） | 接口事件 `[EventInterface]`（有编译期检查、可搜索） |
| 简单一次性通知/旧代码维护 | int/string 直接事件 |
| 热更 AOT 框架层 ↔ 热更业务层 | GameEvent 本体在 TEngine.Runtime（AOT），两侧共用同一张表，天然互通 |
