# 01 架构总览与启动流程

## 1. 分层结构：哪段代码在哪一层

```
┌─────────────────────────────────────────────┐
│ AOT 主包（随 App 一起编译发布，不可热更）      │
│  Launcher.asmdef        Assets/Launcher      │
│  Assembly-CSharp        GameEntry + Procedure│
│  TEngine.Runtime        框架本体              │
│  YooAsset / UniTask / HybridCLR 运行时        │
├─────────────────────────────────────────────┤
│ 热更程序集（打包成 DLL 放 AssetRaw/DLL，      │
│ 运行时 Assembly.Load 加载）                   │
│  GameProto.dll          Assets/.../GameProto  │
│  GameLogic.dll(主逻辑)  Assets/.../GameLogic  │
│   ├─ GameApp      热更入口                    │
│   ├─ GameModule   框架模块门面                │
│   ├─ UIModule     UI 系统（注意：在热更侧！）  │
│   └─ SingletonSystem 热更单例/生命周期中枢     │
└─────────────────────────────────────────────┘
```

判定依据：`Assets/TEngine/Runtime/Core/UpdateSetting.cs` 中 `HotUpdateAssemblies = {GameProto.dll, GameLogic.dll}`、`LogicMainDllName = "GameLogic.dll"`。UI 系统、事件接口都长在 GameLogic 里，意味着**改 UI/逻辑不需要重新出包**。

## 2. 启动链：从按下 Play 到热更代码跑起来

场景 `main.unity` 里摆的是预制体实例：`Assets/TEngine/Settings/Prefab/GameEntry.prefab`（挂 GameEntry/RootModule/Settings）与 `UIRoot.prefab`（UI 根节点），外加相机等 6 个实例。

**第 0 步 · Unity 层引导**
- `RootModule.Awake()`（TEngine/Runtime/Module/RootModule.cs:116）：初始化 Log/Text/Json 三个 Helper、帧率(120)、后台运行、低内存回调注册。之后每帧 `Update()` 驱动 `ModuleSystem.Update()` —— 所有框架模块的心跳源头。
- `GameEntry.Awake()`（GameScripts/GameEntry.cs）：
  1. `ModuleSystem.GetModule<IUpdateDriver>()` 创建隐藏 GameObject 的驱动器（协程/Update/FixedUpdate/LateUpdate 分发）；
  2. 依次触发 Resource/Debugger/Fsm 模块创建；
  3. `Settings.ProcedureSetting.StartProcedure()` 读 `Assets/TEngine/Settings/ProcedureSetting.asset`，反射实例化 11 个流程类塞进 FSM，入口为 **ProcedureLaunch**。

**流程链（Assets/GameScripts/Procedure/，每步做什么）：**

| 顺序 | 流程 | 干什么 |
|---|---|---|
| 1 | `ProcedureLaunch` | `LauncherMgr.Initialize()`（热更前启动 UI）；从 PlayerPrefs 恢复语言与音量设置 → 下一帧进 Splash |
| 2 | `ProcedureSplash` | 闪屏（当前空实现），立即进 InitPackage |
| 3 | `ProcedureInitPackage` | 调 `_resourceModule.InitPackage("DefaultPackage")` 初始化 YooAsset 包。**编辑器下 PlayMode 取自 EditorPrefs "EditorPlayMode"**。成功后按模式分流：EditorSimulate/Offline → InitResources；Host/Web → 打开 LoadUpdateUI 后进 InitResources |
| 4 | `ProcedureInitResources` | `RequestPackageVersionAsync` 拿远端版本 → `UpdatePackageManifestAsync` 更新清单。Host 模式下若断网且 UpdateStyle=Optional，可回退用本地记录版本直接进游戏 |
| 5 | `ProcedureCreateDownloader` | 创建补丁下载器；无差异文件 → 直接 DownloadOver；有 → 弹框提示总量后进下载 |
| 6 | `ProcedureDownloadFile` | 真正下载：注册进度/错误回调，滑动窗口算网速，LoadUpdateUI 显示进度条 |
| 7 | `ProcedureDownloadOver` | 保存本次版本号到 PlayerPrefs("GAME_VERSION") |
| 8 | `ProcedureClearCache` | `ClearCacheFilesAsync` 清掉旧版本无用缓存文件 |
| 9 | `ProcedurePreload` | 按 Tag="PRELOAD" 批量预加载资源（`GetAssetInfos("PRELOAD")`），全部到齐才放行 |
| 10 | `ProcedureLoadAssembly` | **HybridCLR 交接点**（详见 07 篇）：先给 AOT 程序集补元数据（mscorlib/System/TEngine.Runtime/UniTask/YooAsset...），再从 `AssetRaw/DLL` 加载 GameProto/GameLogic 的 TextAsset → `Assembly.Load(bytes)` → 反射找 `GameApp.Entrance` 并调用 |
| 11 | `ProcedureStartGame` | 切入后 `LauncherMgr.HideAllUI()` 收起启动 UI |

**第 N 步 · 热更域接管（GameLogic/GameApp.cs）**
```csharp
public static void Entrance(object[] objects)
{
    GameEventHelper.Init();                    // SourceGenerator 生成的接口事件注册
    _hotfixAssembly = (List<Assembly>)objects[0];
    Utility.Unity.AddDestroyListener(Release); // App 退出时 SingletonSystem.Release()
    StartGameLogic();                          // demo: GameModule.UI.ShowUIAsync<BattleMainUI>()
}
```
从这一行起，运行的就是可热更的 GameLogic 代码。

## 3. 热更侧的"第二套模块体系"

GameLogic 命名空间没有再用 ModuleSystem，而是自己的组合：

- **`GameModule`**（静态门面）：`GameModule.Resource/Audio/Timer/...` 惰性取 ModuleSystem 里的框架模块；`GameModule.UI` 特殊——指向热更侧 `UIModule.Instance`。
- **`SingletonSystem`**（SingletonSystem/SingletonSystem.cs）：所有热更全局对象的注册表。任何 `Singleton<T>.Instance` 首次访问即创建并 Retain；实现了 `IUpdate/IFixedUpdate/ILateUpdate` 的单例会被挂进对应轮询列表，由 `IUpdateDriver` 驱动（和框架模块同一心跳源）。`SingletonSystem.Restart()` 可整体重启游戏（清单例→重载 0 号场景）。
- 单例构造器里有编辑器断言：**必须经 `Instance` 访问**，`new` 出来的会在 Console 报错。

## 4. 一次完整运行的时序图（文字版）

```
Unity Awake
 ├─ RootModule.Awake ──→ Helper/帧率/低内存注册
 ├─ GameEntry.Awake ──→ 建 UpdateDriver/Resource/Debugger/Fsm 模块
 │                      └─ StartProcedure: Launch→Splash→InitPackage
 │                          →InitResources→(下载三连)→Preload
 │                          →LoadAssembly(AOT补元数据+热更DLL)
 │                          →StartGame
 ├─ RootModule.Update ──→ ModuleSystem.Update ──→ 各框架模块
 │                                          └─ UpdateDriver ──→ SingletonSystem.OnUpdate ──→ 热更单例/UIModule
 └─ GameApp.Entrance(反射) ──→ 业务起飞(ShowUIAsync<BattleMainUI>)
```

## 5. 常见疑问

- **为什么 UI 模块在热更侧？** UI 是最常改的部分，放进 GameLogic 后界面迭代免出包。代价是 UI 系统代码本身走 `UIModule.Resource`（IUIResourceLoader）桥接 AOT 的资源模块加载 prefab。
- **改了热更代码怎么生效？** 编辑器下直接编译即可（InitPackage 走 EditorSimulateMode 时 LoadAssembly 直接用已加载程序集，见 ProcedureLoadAssembly.cs:70-73）；真机需走 HybridCLR 打包流程（07 篇）。
- **13 个流程文件里 `UseNativeDialog` 是干嘛的？** 标记该流程是否可用原生弹窗（在游戏内对话框资源就绪前使用的系统级 MessageBox）。
